# ADR-001：20 天版本采用模块化单体，而不是微服务

## 状态
Accepted

## 背景
项目需要在约 132~144 小时内完成可演示、可测试、可部署的企业级闭环。

## 决策
采用一个 FastAPI Backend，但严格拆分：
- api
- agents
- domain
- services
- security
- infrastructure

PostgreSQL、Redis、Milvus 作为独立基础设施。

## 原因
- 单人 20 天项目若直接拆微服务，会把大量时间消耗在服务发现、网络错误、部署和契约维护。
- 模块化单体同样可以体现边界、依赖倒置、测试与可维护性。
- 当吞吐量或团队边界明确后，再把 ingestion / retrieval / agent 拆成独立服务。

## 面试回答
“我不是不会微服务，而是根据团队规模、交付周期和系统复杂度选择了模块化单体。企业级设计首先是控制复杂度，而不是制造复杂度。”
