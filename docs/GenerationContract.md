# DeepSeek接入契约：第一步

## 我的范围

我采用DeepSeek官方接口，先建立“公开证据约束回答”闭环，再扩展问题规划。第一步只实现数据契约、导出边界及离线测试，没有实现网络请求、读取密钥或改变现有问答路径。运行中的镜像没有更新，网站行为保持原样。

## 我如何划分责任

```text
用户问题 → 原有身份/知识库授权 → 检索与来源核验
  → 服务端公开来源许可与问题导出许可 → 最小化导出DTO
  → DeepSeek返回JSON草稿（第二步实现调用）
  → 输出结构/引用/原文检查 + 公司/年份/指标检查（第三步衔接）
  → 后台渲染来源约束回答，或拒答/回退
```

我让模型在已批准证据中选择与问题有关的摘录并组织结构化结果，不让它计算财务值、生成任意SQL、扩大工具权限或确认审核。第一版不显示模型自由编写的金融断言；后续若需要自由摘要，必须增加语义支持校验和独立题库，不能只看到引用编号就认定正确。

## 我允许发送什么

我只允许发送已确认可公开外发的研究问题，以及最多3个公开公告摘录。每条摘录只包含 `citation_id`、公开标题、报告年份、上传摘录页码和原文。问题最多500字符、标题最多200字符、每条原文最多1200字符，超过限制直接拒绝，不默默截断数字或表格。中文字符数不等于token数；后续调用还须计入系统提示及输出预算。

我不发送私有文档、账户信息、角色、用户/工作空间/知识库ID、存储路径、原文件整本内容、完整数据库记录、密钥或历史对话。API密钥未来仅用于HTTPS Authorization认证头，不写入问题、日志或模型消息；“不发送密钥”指不把密钥作为模型内容或发送给非官方目的地，官方接口身份认证本身必须使用密钥。

我把 `public_source_approved`、`actor_authorized`、`source_anchored` 作为服务端内部决策，它们不是API请求参数。第三步必须从服务器维护的公开来源许可记录、实际授权和权威源核验得到，不能由浏览器提交三个true，也不能仅凭有source_url判断公开。

问题本身可能包含用户隐私，因此我要求独立的 `public_query_approved`。第三步需要明确的服务端许可路径或经过批准的固定演示问题，不自动把所有自由输入当成公开问题；未批准时走本地路径，不调用接口。

我补充了凭据、邮箱、手机、身份证、路径和URL等高风险模式拦截。它是额外保守防线，会有误拦截，也无法识别所有隐私、姓名或变形密钥；它不能替代公开来源人工许可与最小化字段设计。

## 我的输入输出格式

允许的输入示例是教学用的公开事实，不是本步实际外发：

```json
{
  "query": "2023年全年每股股息是多少？",
  "query_sha256": "由后台根据规范化问题计算的64位摘要",
  "evidence": [{
    "citation_id": "C1",
    "title": "Public results 2023",
    "report_year": 2023,
    "page_number": 1,
    "quote": "Total dividends of HK$6.50 per share for 2023."
  }]
}
```

上例摘要是说明占位符，不能直接通过实际校验。实际摘要绑定strip后的问题文本，我拒绝摘要不一致、重复引用和跨年份证据包。跨年比较未来需独立契约，不在第一版里混合。

模型正向草稿格式：

```json
{"status":"answered","quotes":[{"citation_id":"C1","quoted_text":"HK$6.50"}]}
```

模型拒答格式：

```json
{"status":"refused","quotes":[],"refusal_reason":"insufficient_evidence"}
```

我拒绝额外字段、没有证据的answered、带事实的refused、重复引用、不存在的引用及编造原文。原文子串匹配只证明引用包含这段文字，不证明这段文字回答了问题；比如原文同时有中期和全年股息，仍要核对请求的指标与年份。HK$是港币，不转换为人民币，不把股息金额当作股息率。

## 我的调用与费用上限

`GenerationPolicy` 默认 `enabled=False`，目的地只能为 `https://api.deepseek.com/chat/completions`：

| 约束 | 第一版上限 |
|---|---:|
| 每个用户请求的外部尝试 | 2次，含重试 |
| 每日外部尝试 | 20次，跨进程统一计数 |
| 每次输出 | 512 tokens |
| 单次请求超时 | 20秒 |
| 整体调用截止时间 | 45秒 |

我在第二步实现实际执行计数与截止时间，不能因为第一步写了字段就声称现有网站已限流。每日计数按明确时区统计，失败和重试也占额度；预算存储不可用时不发送，避免每个进程各算20次。重试只处理有限的暂时性错误，认证失败、不合法输出和权限拒绝不反复请求；超时后供应商可能已经处理并收费，因此重试有重复计费风险。

次数和token限制不是人民币金额的硬上限，还受输入token、模型定价和供应商计费影响。我没有设置充值金额或自动充值。实际模型名称及兼容参数在第二步按官方文档核实，不盲用现有配置中的旧 `deepseek-chat` 别名，不在本步承诺供应商当前价格或固定模型版本。

## 我的失败与验收规则

- 我在密钥缺失、功能关闭、权限不足、公开许可不足或额度耗尽时不外发，保留现有本地路径。
- 我在返回非JSON、空内容、输出截断、未知引用或原文不匹配时拒绝草稿；不能直接显示接口返回正文。
- 我把模型失败与证据不足分开：前者是调用问题，后者是金融来源没有支持。回退不把“模型生成成功”或“新生成答案”写成实际未发生的状态。
- 我不执行来源正文中的命令；原文始终是数据，提示注入不能改变工具、系统指令和输出契约。完整链路的对抗测试在第三/四步补齐。
- 我在日志中只保留请求摘要、供应商/模型标识、耗时、token用量、次数和错误码，不记问题正文、摘录、认证头或密钥。原有系统审计范围独立核对，不能据此保证供应商不保存提交内容。

第四步需要验证正确回答、错误年份/公司/指标、证据不足、私有文档、越权、提示注入、接口故障、截断、日额度与多进程计数。外部真实测试使用固定公开样本，并明确次数预算；当前没有实际外部测试结果。

## 我依据的官方接口说明

我参考[DeepSeek Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)与[JSON Output](https://api-docs.deepseek.com/guides/json_mode/)定义接口和输出格式。JSON模式不等于业务正确，输出达到长度上限时也可能截断，后台必须继续校验。本步不使用任何其他供应商接口。
