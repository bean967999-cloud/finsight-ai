# 公开证据约束回答接入

## 链路和职责

登录身份与工作空间/知识库权限校验 → 请求上下文许可 → 检索 → 本地公司/年份/指标判断 → 原文件和解析来源核验 → 服务端公开问题及文件哈希许可 → 最小摘录导出 → 有限预算调用 → 完整引用复核 → 本地模板呈现。

第一版模型只选择已核验的证据，不自由生成财务解释、不生成 SQL、不执行交易，也不参与问题规划。原文事实及展示模板仍由本地代码负责。

## 核心位置

- `services/generation_answer.py`：接线、请求上下文、公开问题/原文件哈希许可、完整引用复核和回退。
- `Evaluation/PublicGenerationPolicyV1.json`：服务端维护的两份公告摘录和四个公开问题；不是客户端可修改的批准字段。
- `api/routes/agent.py`：完成原有权限检查之后建立上下文；研究工具线程使用现有 `copy_context()` 传播许可。
- `workers/deployment.py`：配置了受保护文件路径时才包装原回答服务；评估仍绑定原本地服务，避免隐式收费。
- `GenerationReport`：`local`、`generated`、`fallback`，仅记录固定原因和最多两次尝试，无密钥和原始错误体。

## 金融口径

全年每股股息是该报告年度每股分配总额，不等同于单次中期股息，也不是股息率。报价 `HK$6.50 per share for 2023` 必须保留年份、港元和每股口径。完整原句复核避免仅输出数字而产生口径丢失。

## 部署

在原有 Compose、GpuRuntime、GatewayRuntime 和 QuestionBank/EvaluationRuntime 四层基础上，最后添加 `Deployment/GenerationRuntime.json`。它使用本次新镜像并仅向接口挂载只读 `/Secrets/DeepSeek.env`。密钥不进入镜像、前端或代码仓库。

如果配置非法，接口启动失败，不能忽略错误后悄悄进行外部请求；如果密钥未填、调用失败或输出不合格，保留已核验的本地答案。没有本地可核验事实时不请求外部模型。

回退到旧运行版本时使用原四层重新启动本项目的 api/worker/dispatcher/gateway；原镜像、数据卷保留。不要使用 `down -v`。之后的常规重启要包含新的第五层，否则不会使用本次接线。

## 验收范围

离线模拟可以验证权限范围隔离、完整原句核验、失败回退和持久化；它不能证明真实密钥有效、供应商可达、真实模型正确率或费用。公开问题白名单是有意设置的第一版限制；未批准的新问法仍走本地答案。
