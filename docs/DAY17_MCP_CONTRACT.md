# Day17 Step1：金融工具接口与安全边界

本步只建立与传输方式无关的输入、输出和权限契约，尚未启动 MCP 服务或接入外部客户端。核心模型位于 `src/finsight/domain/mcp_tool_contracts.py`。后续适配器应复用已有应用服务，不复制计算公式或另开 SQL 执行通道。

| 工具 | 输入重点 | 输出重点 | 最低权限 |
| --- | --- | --- | --- |
| `search_financial_documents` | 工作空间、知识库、问题、公司/文档/年份过滤 | 最多 20 条带文档和页码的证据引用、限制说明 | `knowledge_read`，还须核验知识库实际归属目标工作空间 |
| `query_financial_data` | 工作空间、问题、意图、实体、指标、时间、排序；最多 100 行 | 受限行集、列名、查询哈希和警告；不直接暴露任意 SQL 输入 | `research_submit`，后续仍须走原有指标解析、只读编译与数据范围控制 |
| `calculate_portfolio_risk` | 工作空间、至少三点且有限的正价格、置信度、交易日等 | 确定性风险指标及“调用方提供价格、未独立核验来源”的限制 | `research_submit` |
| `generate_research_brief` | 工作空间、问题、可选知识库/价格、可选发布申请 | 回答状态、限制、审核状态和线程编号；待审核时不得输出最终回答 | `research_submit`；申请发布还需 `release_request` |

身份只能由服务端解析为 `ToolCallContext.principal`，不接受工具参数中的角色或用户编号。所有输入都拒绝未知字段；权限默认拒绝。工具错误采用有限的错误代码，客户端返回消息应为安全、概括性的说明，不能回显令牌、原始异常、SQL 参数或未授权文档内容。请求编号用于后续安全追踪，不属于调用方可以指定的权限依据。

这里的 `tool_access_allowed` 只检查角色和资源授权，不负责证明知识库 ID 确实属于传入工作空间；后续文档检索适配器必须向权威存储核对归属。它也没有完成实际调用接线、失败映射、审计落库或客户端联调，不应被描述成四个工具已可用。

金融边界：风险工具返回数值不等于价格来源已核验；研究工具获取证据不等于已完成财务结论复核；申请发布不能绕过人工确认。

## Step2：组合风险计算适配器

`PortfolioRiskTool` 已把 `calculate_portfolio_risk` 契约接到现有 `RiskEngine`。调用顺序为：先开始操作审计，再按服务端身份检查工作空间和 `research_submit` 权限，再执行确定性计算，最后完成审计并返回结果。审计开始失败时不执行计算；审计完成失败时不向调用方返回计算结果。拒绝访问、非法输入、计算故障分别使用受限错误代码与概括性消息，不回显原始异常或价格。

这里的“组合”输入是调用方提供的**组合净值或价格序列**，不是逐项持仓、权重及协方差矩阵。工具沿用已有收益率、波动率、回撤、历史 VaR/CVaR 公式，不自行抓取行情，也不验证证券、日期与来源。输出强制检查指标为有限数，并保留来源限制。当前仅为可注入审计服务的应用层适配器；真正的 MCP 注册、客户端身份解析及传输层调用将在后续步骤完成。

## Step3：结构化财务查询适配器

`FinancialQueryTool` 已接到 `StructuredQueryService`，其后仍依次经过指标解析、受控 SQL 编译、只读语法守卫及 PostgreSQL 只读执行器。工具输入不接受原始 SQL，最多请求 100 行；输出不回传 SQL 文本或参数，仅回传列、受限行集、SQL 哈希与警告。`Decimal` 按字符串输出，日期按 ISO 日期格式输出，避免金融精度与可读性问题。未知数据库值类型、行数或列名不一致、非有限数值会阻止结果发布。

应用层调用遵循先审计、再按服务端身份核对 `research_submit` 和工作空间授权、再查询、最后完成审计的顺序。审计不可用时不执行或不发布结果；查询异常使用概括性错误，不回显 SQL、参数和数据库异常。当前财务表是已有的共享数据表：工作空间授权控制谁能调用该工具，**不等于**数据库行已经按工作空间隔离。若以后接入私有持仓或客户财务数据，需要先增加行级归属过滤与对应验收；不能仅沿用现有的角色检查。

## Step4：金融文档检索适配器

`FinancialDocumentTool` 已复用 `KnowledgeScopeService.workspace_for` 和现有 `EvidenceSearchService`。它先开始审计，再检查服务端身份对目标知识库的读取权限，再向权威归属服务确认该知识库确实属于请求的工作空间，最后才检索。无权限、归属不符或知识库不存在均不进入检索链，不向调用方区分资源存在性。实际查询过滤条件始终包含目标知识库编号。

输出最多 20 条文档引用，每条保留文档 ID、片段 ID、文档标题、页码、最多 2000 字的片段，以及片段是否截断和原引用的 `pending`/`verified`/`rejected` 状态。默认检索结果可能仍是 `pending`，工具会注明“检索片段不是经核验的金融结论”。没有命中时返回空引用和明确限制，不虚构来源；服务或审计不可用时只返回安全错误，不回显文档正文或内部异常。当前仍未启动真实向量服务，也没有获得 Day16 文档题的真实检索评分。

## Step5：研究简报适配器

`ResearchBriefTool` 复用现有研究规划、图执行和保守回答策略。它先开始审计，检查 `research_submit`；申请发布还需 `release_request`。若涉及知识库，还要有读取授权并核对实际归属；规划结果需要文档而未提供知识库时直接拒绝。普通研究返回回答状态、正文和限制；`insufficient_evidence` 或 `refused` 必须附限制，不能伪装成已核验结论。

申请发布必须有持久化检查点服务。工具调用现有 `ResearchCheckpointService.start` 后，只接受 `awaiting_review` 阶段，输出 `review_pending=true`、线程编号、回答状态和限制，**不返回待审核正文**。人工复核与后续是否可对外发布仍遵循已有流程；工具本身不会代替审核人做确认。当前本地测试使用内存检查点验证暂停逻辑，不等于 PostgreSQL 持久化或外部客户端联调已完成。

## Step6：本地服务与客户端联调

四个适配器已注册在 `build_mcp_server()` 中，客户端通过 `tools/list` 发现的名称正是本页表格中的四项。调用参数以 `payload` 为根对象，内部字段由 Step1 的契约校验；服务端解析的身份和请求编号不出现在工具参数中。业务适配器返回受限错误时，协议层将其转成安全的工具错误，客户端可看到错误标记和错误代码，而不是把错误误认作成功数据。

实际本地入口是 `uv run python -m finsight.workers.mcp_stdio`，使用标准输入输出通信，**不监听任何端口**。本地客户端须以同一项目虚拟环境中的 Python 启动它，并通过安全的进程环境提供短期 `FINSIGHT_MCP_ACCESS_TOKEN`；项目还需要有效的签名密钥与 PostgreSQL。入口启动前校验身份，每次工具调用都重新解析令牌和当前授权，令牌不能作为工具参数传入。不要把真实令牌写入配置文件、命令行参数或提交记录。

文档检索还需要本地 `FINSIGHT_BGE_M3_PATH`、`FINSIGHT_RERANKER_PATH`、`FINSIGHT_RERANKER_VERSION`，以及已配置的 Milvus 集合。缺少全部本地模型配置时，文档工具明确返回不可用；只配置一部分则拒绝启动。不会自动下载模型。文档研究简报使用同一检索依赖，故该能力也受此限制。无这些依赖时，风险工具仍可在身份、审计和数据库检查点服务具备后运行。

已用官方客户端完成四工具的进程内发现与调用，并另以标准输入输出子进程验证工具发现和风险计算调用；同时测试查看者拒绝、身份解析失败、缺少启动凭据等边界。子进程使用受控测试身份和内存审计，不代表真实数据库、真实文档检索或外部桌面客户端已完成生产验收。正式运行仍须用真实身份、PostgreSQL 审计、知识库归属、本地模型和向量库复核整条链路。
